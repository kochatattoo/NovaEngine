## 2. Соглашения по оформлению

### 2.1 Формат

- **Markdown** (CommonMark + GFM), **UTF-8**.
- Имена файлов: `NN_Название.md` (NN — двузначный номер).
- Первый заголовок: `# NN — Title`.
- Блок статуса в начале (если применимо):

```markdown
> **Статус:** 🟢/🟡/🔴/⚪
```

- Эмодзи-статусы:
  - 🟢 стабильно
  - 🟡 в работе
  - 🔴 сломано
  - ⚪ зарезервировано

### 2.2 Структура файла подсистемы

```
# NN — Название

> **Статус:** ...

## Класс X
**Файлы:** ...

## Поля / Методы
(таблица или код)

## Использование
(пример)

## Известные ограничения

## TODO
(список)
```

## 3. Когда обновлять

| Изменение в коде | Где обновить |
|---|---|
| Новый публичный класс/метод в `Engine/Include/` | Соответствующий файл в `02_Подсистемы/` |
| Изменение API Lua | `03_Скриптинг_на_Lua/01_Lua_API_справочник.md` + соответствующий `02_Подсистемы/*.md` |
| Новый пример Lua-скрипта | `03_Скриптинг_на_Lua/02_Lua_примеры.md` |
| Изменение vcxproj / build | `05_Сборка_и_запуск/01_Сборка_проекта.md` |
| Закрытый TODO из бэклога | `06_План_разработки/01_Текущее_состояние.md` + `CHANGELOG.md` |
| Завершён спринт | `CHANGELOG.md` + `Reports/YYYY-MM-DD.md` (новый файл) |

Документация дублируется в:
- `D:\ENGINE\NovaEngine\docs\` (в репо, коммитится в git)


## 5. CHANGELOG.md

Каждый спринт = новая запись **в самом верху**:

```markdown
## [v0.X.Y] — YYYY-MM-DD

### Спринт "Название" — ЗАВЕРШЁН

**Код:**
- 🟢 файл.cpp — что изменилось

**Документация (синхронизирована):**
- 🟢 docs/02_Подсистемы/X.md — что обновлено

**См. также:** отчёт `Reports/YYYY-MM-DD.md`.
```

## 6. Reports/

Каждый спринт = новый файл `Reports/YYYY-MM-DD.md` со структурой:

```markdown
# Отчёт за YYYY-MM-DD — Спринт v0.X.Y

> **Спринт:** ...
> **Статус:** ✅ ЗАВЕРШЁН

## Что сделано
(таблица или список)

## Что НЕ сделано (перенесено в vN.M)

## Файлы изменены

## Уроки

## Что дальше
```

## 7. Что нельзя трогать

- Исторические отчёты в `Reports/` — после создания НЕ править. Дополнения — в новый отчёт.
- Версионные секции в `CHANGELOG.md` — после merge НЕ править. Дополнения — в новую секцию.

## 8. Подводные камни

### 8.1 Кириллица в PowerShell + OneDrive

`bash` через PowerShell может не находить файлы с кириллическими путями. Используй `[System.IO.File]::ReadAllText()` / `Copy-Item -Force` через .NET API. Или bash с переменной `OutputEncoding` = UTF-8.

### 8.2 Параллельные write/edit могут конфликтовать

Несколько одновременных `Edit` к одному файлу могут потерять изменения. Делай последовательно или используй bash-скрипты.
