## Манифест vcpkg

`vcpkg.json` минимален — только glm:

```json
{
  "name": "nova-engine",
  "version-string": "0.1.0",
  "dependencies": [
    "glm"
  ]
}
```

Включён manifest mode: `<VcpkgEnableManifest>true</VcpkgEnableManifest>` в `Engine.vcxproj`.

## Конфигурация vcpkg

`vcpkg-configuration.json` задаёт baseline-версию и registries (если есть). Файл генерируется IDE, править руками обычно не нужно.

## Пути включения в проектах

### `Engine.vcxproj` → `AdditionalIncludeDirectories`

- `$(SolutionDir)Libraries`             — корень libraries (sol, EnTT)
- `$(SolutionDir)Libraries\lua\src`     — заголовки Lua (`lua.h`, `lauxlib.h`, …)
- `$(ProjectDir)Libraries`              — зарезервировано (пусто)
- `$(ProjectDir)Include`                — заголовки движка
- `$(ProjectDir)Source`                 — внутренние заголовки (stb, glad)

### `SandBox.vcxproj` → `AdditionalIncludeDirectories`

- `$(SolutionDir)Libraries`
- `$(SolutionDir)Engine\Include`
- `$(SolutionDir)Libraries\lua\src`
- `$(SolutionDir)Engine\Sources`         — ⚠️ лишний путь (опечатка, см. ниже)
- `$(ProjectDir)Source`                  — собственные заголовки игры

## Линковка

### `Engine` — `StaticLibrary (.lib)`

Все исходники Lua 5.4 (`*.c` из `Libraries/lua/src/`) **добавлены в проект Engine** через `<ClCompile Include="..\Libraries\lua\src\lapi.c"/>` и т.д. Это даёт `lua.lib` в составе `Engine.lib`.

⚠️ Замечание: из-за этого проект Engine **зависит от C-runtime Lua-исходников**. Если когда-нибудь захочется собирать движок как DLL — Lua нужно будет выделить в отдельный проект.

### `SandBox` — `Application (.exe)`

- `ProjectReference` → `Engine.vcxproj` (даёт `Engine.lib`).
- `AdditionalDependencies` → `opengl32.lib` (для WGL).
- `SubSystem` → `Console` (консольное окно для логов `printf`).

## Особенности glad

glad используется **без автоматической загрузки**. Это сознательное архитектурное решение:

- `Engine/Include/glad/gl.h` — обычный glad-header с объявлениями `glad_gl*` функций и `glad_gl*` указателями.
- `Engine/Source/glad/gl.c` — содержит **только определения указателей** (без `loader.Load(...)`).
- `Engine/Source/Renderer/GraphicsContext.cpp` — функция `GetAnyGLFuncAddress(name)`, которая комбинирует `wglGetProcAddress` и `GetProcAddress(opengl32.dll)`, и явно вызывает её для **каждой** используемой GL-функции.

**Почему так:** явный список функций проще аудировать, не нужно таскать glad-loader, и нет скрытых `dlopen/dlsym` для portability.

**Цена:** при добавлении новой GL-функции нужно вручную прописать её загрузку в `GraphicsContext::Init`. Сейчас загружены:

- `glViewport`, `glClear`, `glClearColor`, `glEnable`, `glDisable`
- `glCreateShader`, `glShaderSource`, `glCompileShader`, `glGetShaderiv`, `glGetShaderInfoLog`, `glDeleteShader`
- `glCreateProgram`, `glAttachShader`, `glLinkProgram`, `glUseProgram`, `glGetProgramiv`, `glGetProgramInfoLog`, `glDeleteProgram`
- `glGetUniformLocation`, `glUniform1i`, `glUniform4f`, `glUniformMatrix4fv`
- `glGenBuffers`, `glDeleteBuffers`, `glBindBuffer`, `glBufferData`
- `glGenVertexArrays`, `glDeleteVertexArrays`, `glBindVertexArray`
- `glEnableVertexAttribArray`, `glVertexAttribPointer`
- `glDrawArrays`, `glDrawElements`
- `glActiveTexture`, `glGenTextures`, `glDeleteTextures`, `glBindTexture`, `glTexImage2D`, `glTexParameteri`
- `glBlendFunc`, `glDepthFunc`, `glCullFace`, `glFrontFace`
- `glPixelStorei` (для stb_image unpack-alignment)

Если добавляете новую — допишите строку в `GraphicsContext::Init`.

## Конфликты и подводные камни

1. **`std::min/max` vs `NOMINMAX`.** В `Window.h`, `KeyCodes.h` объявлен `#define NOMINMAX` ПЕРЕД `#include <Windows.h>`. Без него `std::min` ломается на `min`/`max`-макросах из windows.h.
2. **Двойное подключение windows.h.** Если windows.h попадает в публичный заголовок движка (как `Window.h`), нужно следить, что вызывающий код не включает его повторно с конфликтующими `NOMINMAX`/`min`/`max`.
3. **Lua C-API vs C++.** Lua написана на C, добавлена в C++-проект. Несовместимости имён нет (lua использует `extern "C"` в `lua.h`).
4. **EnTT и `entt::entity` vs `entt::registry`.** В `ECS::World` обёртка минимальна, чтобы не светить `entt` в публичных заголовках игр. Прямое обращение к `World::GetRegistry()` — последний козырь.
5. **stb_image / stb_truetype — реализация в .cpp.** В отличие от стандартного подхода (реализация прямо в .h через `STB_IMAGE_IMPLEMENTATION`), здесь сделаны обёртки в `Source/stb/{stb_image.cpp,stb_truetype.cpp}`, которые просто `#include` соответствующий .h с нужным define. Это позволяет изолировать публичный API.

## Где смотреть, если что-то не компилируется

| Симптом | Причина |
|---|---|
| `glad/glXxx` undefined reference | Забыли добавить ручную загрузку в `GraphicsContext.cpp` |
| `lua.h: No such file` | Пропал `$(SolutionDir)Libraries\lua\src` в AdditionalIncludeDirectories |
| `sol/sol.hpp: No such file` | Пропал `$(SolutionDir)Libraries` или папка `Libraries/sol` пуста |
| `EnTT/entt/entt.hpp: No such file` | Папка `Libraries/EnTT` пуста или путь не указан |
| `LNK2019: wglCreateContextAttribsARB` | Не вызвали `wglGetProcAddress` в `GraphicsContext` (для core-профайла) |
| `std::max` ambiguous | Не объявлен `NOMINMAX` |
| `glad.h: redefinition of typedef` | Дважды подключили `glad/gl.h` |
