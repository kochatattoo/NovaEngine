# 04 — Долгосрочный план (3–6 месяцев)

> **Горизонт:** 3–6 месяцев
> **Цель:** v0.3 — v0.5 — превращение в "production-ready" 2D-движок

## 🎯 Стратегические цели

### v0.3 — "Полноценный 2D-движок" (3–4 месяца)

1. **Звук**
   - [ ] Интеграция `miniaudio` (header-only, проще OpenAL).
   - [ ] `AudioSystem` — singleton, `PlaySound(path)`, `PlayMusic(path)`, `StopAll()`.
   - [ ] Поддержка .wav, .ogg, .mp3.
   - [ ] Lua-биндинги: `PlaySound(path)`, `SetMusicVolume(float)`.
   - [ ] Звуки в Match3: совпадение, фейл, перемешивание.

2. **Сериализация**
   - [ ] Формат `NovaScene` (JSON): список entity, компонентов, properties.
   - [ ] `Scene::SaveToFile(path)`, `Scene::LoadFromFile(path)`.
   - [ ] Поддержка префабов (entity-шаблонов).
   - [ ] Hot reload сцен.

3. **Сцены и переходы**
   - [ ] `SceneManager` — стек сцен, `PushScene`, `PopScene`, `ReplaceScene`.
   - [ ] `SceneTransition` — fade in/out.
   - [ ] Сохранение состояния текущей сцены.

4. **Физика (опционально)**
   - [ ] Интеграция Box2D или собственная простая 2D-физика.
   - [ ] `Rigidbody2DComponent`, `Collider2DComponent`.
   - [ ] Система `PhysicsSystem` (fixed timestep).
   - [ ] Collision events.

5. **UI расширение**
   - [ ] `TextBox` (ввод текста).
   - [ ] `ScrollView`.
   - [ ] `LayoutGroup` (горизонтальный/вертикальный).
   - [ ] `ModalDialog`.

6. **Editor / Inspector**
   - [ ] ImGui overlay в debug-сборке.
   - [ ] Дерево сцены, инспектор компонентов, drag-n-drop ресурсов.
   - [ ] Gizmos для камеры, transform, anchor.

**Критерий:** Match3 + аудио + сохранение прогресса в JSON + переход на другую сцену через SceneManager.

### v0.4 — "Полировка" (4–5 месяцев)

1. **Сборка и дистрибуция**
   - [ ] CMake-проект (в дополнение к vcxproj).
   - [ ] Установщик (Inno Setup / WiX).
   - [ ] Поддержка Release-сборки с LTO.
   - [ ] CI/CD (GitHub Actions): сборка + тесты.

2. **Тесты**
   - [ ] Unit-тесты (Catch2 или doctest): `Match3Board`, `OrthographicCamera`, `ResourcePool`.
   - [ ] Integration-тесты: запуск Sandbox с эталонным скриншотом.
   - [ ] Coverage > 60%.

3. **Производительность**
   - [ ] Профилирование через Tracy / Superluminal.
   - [ ] Оптимизация SpriteBatcher (см. v0.2).
   - [ ] Multi-threaded asset loading.
   - [ ] Job system (если рендер станет узким местом).

4. **Расширенный рендеринг**
   - [ ] Render targets / Framebuffers (для post-effects).
   - [ ] Post-processing: blur, bloom, color grading.
   - [ ] 2D-lighting (normal maps + light entities).
   - [ ] Particle systems (CPU + GPU).

5. **Расширенный Input**
   - [ ] Gamepad (XInput, SDL2 GameController).
   - [ ] Touch input (для будущей мобильной версии).
   - [ ] Input rebinding (Action Maps).

6. **Networking (опционально)**
   - [ ] ENet / GameNetworkingSockets интеграция.
   - [ ] Client/Server abstraction.
   - [ ] Replication для entity/components.

**Критерий:** движок используется для второй игры (например, top-down RPG или puzzle).

### v0.5 — "Кроссплатформенность" (5–6 месяцев)

1. **Linux**
   - [ ] `Window` через X11.
   - [ ] `GraphicsContext` через GLX (или EGL).
   - [ ] `Input` через XInput2.
   - [ ] Сборка CMake + GCC/Clang.

2. **macOS**
   - [ ] `Window` через Cocoa.
   - [ ] `GraphicsContext` через NSOpenGL (или Metal — долгосрочно).
   - [ ] `Input` через NSEvent.
   - [ ] Поддержка Apple Silicon (ARM64).

3. **Web (опционально)**
   - [ ] Emscripten-сборка.
   - [ ] WebGL 2.0 backend.
   - [ ] File System API для ассетов.

4. **Mobile (опционально)**
   - [ ] Android (NDK + EGL).
   - [ ] iOS (Metal или OpenGL ES).

**Критерий:** NovaEngine запускается на Windows, Linux, macOS; одна игра собирается под все три.

## Принципы планирования

- **Каждый мажор = 1 месяц.** v0.2 = месяц 1, v0.3 = месяц 2-3, v0.4 = месяц 3-5, v0.5 = месяц 5-6.
- **Каждая фича = подтверждённое пользователем.** Перед началом работы — обсудить scope и критерий готовности.
- **Документация обновляется в том же коммите**, что и код.
- **Каждая версия = git tag + release notes.**

## Что может ускорить разработку

1. **Внешний контрибьютор.** Если кто-то готов помогать — отдать ему Sandbox/Examples, чтобы ядро делал сам.
2. **Закрытые TODO из [05_Backlog_идеи](05_Backlog_идеи.md)** — могут дать быстрые победы.
3. **Готовые ассеты** — если пользователь сделает 2-3 игры, появятся реальные use-case'ы.
4. **Профилирование** — без него оптимизации вслепую.

## Что может тормознуть

1. **Scope creep** — добавлять фичи, не входящие в текущую версию.
2. **Преждевременная оптимизация** — без профилирования.
3. **Документация отстаёт от кода** — решается правилом "код+дока в одном коммите".
4. **3D-направление** — даже не начинать, пока 2D не готово.

## Definition of Done для v0.3–v0.5

- [ ] **v0.3:** Match3 имеет звук, прогресс сохраняется в файл, есть сцены MainMenu/Game/GameOver.
- [ ] **v0.4:** CI собирает проект, тесты проходят, профайлер показывает стабильные 60 FPS на 10000 спрайтов.
- [ ] **v0.5:** NovaEngine работает на Windows + Linux + macOS, две собранные игры в каждой.
