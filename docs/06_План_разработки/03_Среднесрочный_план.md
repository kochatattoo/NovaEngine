# 03 — Среднесрочный план (1–2 месяца)

> **Горизонт:** 4–8 недель
> **Цель:** v0.2 — ECS-миграция, batching, sandbox для Lua

## 🎯 Sprint Goals (v0.2)

### 1. ECS-миграция (приоритет #1)

**Цель:** `Scene` становится тонкой обёрткой над `ECS::World`. Все `GameObject` → entities с компонентами.

#### 1.1. Базовые ECS-компоненты (неделя 1)

- [ ] Вынести текущий код из Scene-компонентов в POD-структуры:
  - `TransformComponent` (уже есть, проверить поля)
  - `SpriteComponent` (расширить: PPU, alignment, color, isUI)
  - `TextComponent` (новый)
  - `CameraComponent` (новый, для GameCamera и UICamera)
  - `AnchorComponent` (новый)
  - `ButtonComponent` (новый)
  - `ScriptComponent` (новый)
- [ ] Адаптеры Scene→ECS: `GameObject` хранит `entt::entity` + ленивые обёртки `TransformECS`, `SpriteRendererECS`, и т.д., которые читают/пишут ECS-компоненты.

#### 1.2. Системы (неделя 2)

- [ ] `TransformSystem` — вычисление world matrix (если появится parent-child).
- [ ] `SpriteRenderSystem` — итерация по `(TransformComponent, SpriteComponent)`, **с batching** (см. п.2).
- [ ] `TextRenderSystem` — итерация по `(TransformComponent, TextComponent)`.
- [ ] `AnchorSystem` — пересчёт при ресайзе окна.
- [ ] `ButtonSystem` — hit-test + onClick.
- [ ] `LifetimeSystem` — удаление помеченных entity.

#### 1.3. Сцены (неделя 2)

- [ ] `Scene` теперь хранит `std::unique_ptr<ECS::World>`.
- [ ] `CreateEntity(name)`, `DestroyEntity(id)`.
- [ ] `OnStart`/`OnUpdate`/`OnRender` запускают системы в правильном порядке.
- [ ] `OnRender` заменяется на `RenderSystem`.

#### 1.4. Совместимость (неделя 3)

- [ ] В `Sandbox` Match3 работает **через ECS** (плитки, кнопка, UI).
- [ ] `Scene/GameObject/Component` остаются как **legacy API** (deprecated), но работают.
- [ ] Миграция старых Lua-скриптов — без изменений (биндинги `GameObject`/`Transform` работают как обёртки).

**Файлы:** `Engine/Include/ECS/*`, `Engine/Source/ECS/*`, `Engine/Include/Scene/*` (legacy), `Engine/Source/Renderer/SpriteRenderer.cpp`, `Engine/Source/Renderer/TextRenderer.cpp`, `Engine/Source/Scene/*`, `Engine/Source/UI/*`, `SandBox/assets/scripts/game_match3.lua`.

**Критерий:** `git grep "AddComponent_Transform" SandBox` находит использование, но внутри `AddComponent_Transform` идёт через ECS.

### 2. Sprite batching (неделя 2-3)

**Цель:** 1 draw call на тысячи спрайтов.

- [ ] `SpriteBatcher` — собирает все `SpriteComponent` (одинаковый шейдер/текстура) в один VBO.
- [ ] Текстурные атласы (опционально) — собрать несколько текстур в один VBO с разными UV.
- [ ] Инстансинг через `glDrawElementsInstanced` (как fallback).
- [ ] `Scene::OnRender` теперь — 1 (или несколько) draw call вместо N.

**Файлы:** `Engine/Source/Renderer/SpriteBatcher.{h,cpp}` (новый), изменения в `Engine/Source/Renderer/SpriteRenderer.cpp`.

**Критерий:** 1000 спрайтов в Match3 = ≤5 draw calls (vs 1000 сейчас).

### 3. Lua sandbox (неделя 3)

- [ ] Ограничить библиотеки: разрешить `base`, `math`, `string`, `table`, `os` (только time), `package.path` для require.
- [ ] Запретить `io`, `os.execute`, `os.remove`, `os.rename`, `debug`.
- [ ] Ограничить `require` путём `package.path`.
- [ ] Добавить лимит на кол-во инструкций в кадр (через `debug.sethook` + counter, bail out после 1M).

**Файлы:** `Engine/Source/Lua/LuaManager.cpp`.

**Критерий:** `os.execute("calc")` в Lua → ошибка, не открывает калькулятор.

### 4. Камера — zoom и follow (неделя 4)

- [ ] `OrthographicCamera::SetZoom(float factor)` — масштабирование.
- [ ] `OrthographicCamera::FollowTarget(entity)` — следование за entity (плавно).
- [ ] `ScreenToWorldPoint` учитывает zoom.

**Файлы:** `Engine/Include/Renderer/OrthographicCamera.h`, `Engine/Source/Renderer/OrthographicCamera.cpp`.

**Критерий:** Match3 работает с zoom=2.0 (клетки в 2 раза крупнее).

### 5. Анимации перемещения плиток (неделя 4)

- [ ] `Match3Tweener` — плавно интерполирует позицию плитки от A к B за N мс.
- [ ] `Match3Board::ApplyGravity` теперь не мгновенный, а с tween-ами.
- [ ] `Match3Board::RemoveTiles` — fade-out альфа за 200мс.
- [ ] Lua-скрипт ждёт завершения анимации перед следующим шагом (через `sol::coroutine` или promise).

**Файлы:** `SandBox/Source/Game/Match3Tweener.{h,cpp}` (новый), `SandBox/Source/Game/Match3Board.cpp`, `SandBox/assets/scripts/game_match3.lua`.

**Критерий:** плитки плавно падают, плавно исчезают.

## Риски

| Риск | Митигация |
|---|---|
| ECS-миграция занимает 3 недели, а не 1 | Сократить scope: только Match3, не весь Sandbox |
| Sprite batching ломает текст | Сделать batching только для SpriteComponent, не для TextComponent |
| Lua sandbox ломает os.time | Разрешить `os.time` явно (для таймеров) |
| Производительность не растёт | Сделать профилирование ДО batching, чтобы знать bottleneck |
