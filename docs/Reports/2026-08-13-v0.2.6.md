### v0.2.6 — SpriteRenderSystem

**Файлы:**
- `Engine/Include/ECS/Systems/SpriteRenderSystem.h` (новый)
- `Engine/Source/ECS/Systems/SpriteRenderSystem.cpp` (новый)

**Что делает:** рендерит все entities с `(TransformComponent, SpriteComponent)` напрямую через OpenGL — без `GameObject` / `Component` / `SpriteRenderer`. Использует статический quad VAO/VBO (один на всё приложение). Без батчинга пока (рисуем каждый entity отдельным draw call).

```cpp
// Engine/Include/ECS/Systems/SpriteRenderSystem.h
namespace NK::ECS {
    class SpriteRenderSystem {
    public:
        static void Render(
            const World& world,
            const NK::OrthographicCamera& camera,
            std::shared_ptr<NK::Shader> shader
        );
    };
}
```

**Использование в Match3Game:**
```cpp
m_SpriteShader = std::make_shared<NK::Shader>(vertexSrc, fragmentSrc);
m_WhiteTexture = NK::Texture2D::CreateSolidColor(255, 255, 255, 255);
m_System->SetSpriteTexture(m_WhiteTexture);

void Match3Game::Render() {
    const auto& camera = Engine::Get().GetScene().GetGameCamera();
    NK::ECS::SpriteRenderSystem::Render(*m_World, camera, m_SpriteShader);
}
```

## Архитектурные решения

### Почему SpriteRenderSystem, а не отдельный SpriteRenderer на каждую entity?

`SpriteRenderer : public Component` — привязан к `GameObject`. Каждый рендер требует `m_Owner->GetComponent<Transform>()` + `m_Texture + m_Shader`. Для 100 плиток это **100 SpriteRenderer**, **100 GameObject**, **100 Transform** (в Scene), **100 SpriteRenderer::OnUpdate** каждый кадр.

**SpriteRenderSystem** рисует все entities из `World` напрямую через OpenGL — один VAO/VBO на всех, без `GameObject` overhead.

### Почему 1 белая текстура, а не 6 цветных?

Старый код (Lua-скрипт) создавал 6 текстур через `CreateSolidColorTexture(r, g, b, 255)`. Это давало 6 разных текстур, и в `OnTileChanged` мы переключали `SetTexture(tex)`. **Оверкилл**: достаточно одной белой 1x1 текстуры + `Color` uniform. Шейдер делает `tex * u_Color`, и мы получаем любой цвет.

### Почему в `Update` идёт `m_System->Update(dt)` (сейчас пусто), а в `Render` — `m_System->Render()` или `SpriteRenderSystem::Render`?

`Update` — игровая логика (анимации, гравитация во времени, таймеры). `Render` — рисование. **Разделение ответственности**. Сейчас `m_System->Update` пусто (анимаций нет), но в будущем там будут fall/glow/etc.

### Почему SpriteRenderSystem не принимает `Shader&` напрямую, а `shared_ptr<Shader>`?

В будущем SpriteRenderSystem может иметь default shader (если передан nullptr) — например, встроенный "DefaultSprite" шейдер из Engine. Сейчас — Match3Game всегда передаёт свой shader. `shared_ptr` — для гибкости (если шейдер шарится между системами).

## Известные ограничения (TODO v0.3+)

- **Нет батчинга** — каждый entity = отдельный draw call. 100 плиток = 100 draw calls. На современных GPU это всё равно < 1ms, но для серьёзных сцен нужен батчинг.
- **Нет Z-sort** — порядок отрисовки определяется порядком в `view`. Для 2D-игр это обычно ОК, но для Z-sorted (isometric) нужна сортировка.
- **Нет UI в ECS** — UI по-прежнему в `Scene::m_UIObjects` (через `SpriteRenderer`).
- **`TransformComponent::Scale` используется напрямую** — `renderW = 0.5 * Scale.x`. В `SpriteRenderer::Render` для игрового мира Scale игнорируется (TODO v0.1.3+). В SpriteRenderSystem Scale уважается. Это OK, потому что SpriteRenderSystem — новый путь.

## Уроки

1. **EnTT `view.each(lambda)` иногда не компилируется** с MSVC + сложными лямбдами (ошибка в `<tuple>` строка 1057 — invocation проверка). Workaround: обычный `for (auto entity : view) { view.get<T>(entity); }`.
2. **`const entt::registry&` для `view`** — нужно `non-const` для `view.get<T>()` (которое возвращает `T&`). Workaround: `const_cast` или сделать `World::GetRegistry()` non-const (но const-вариант лучше для читаемости).
3. **Forward-declaration + `std::shared_ptr<T>`** — нужна явная `class T;` декларация в правильном namespace, не в qualified form (`NK::T` после `class NK::T;` в namespace NK).
4. **xcopy /d глючит** в post-build event — заменил на `/y /e /r /i` (уже сделано в v0.2.5).
